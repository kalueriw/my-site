I study Computer Science at BiUH. This site is written by hand, one line at a time — which means when something breaks, I am the one who has to understand why.

What I am learning

  • HTML — what each part of a page is, and why the right element makes the page work for more people.
  • CSS — what it looks like, and how one rule can change twenty cards at once.
  • JavaScript — what it does, and how to keep it from getting into a state it cannot get out of.

Most of my answers come from MDN Web Docs; the second place I check is the W3C validator, which is less forgiving and more useful.

How this site is put together

Five pages share one stylesheet and one navigation. The navigation is written once, in nav.html, and a small script fetches it into every page — so adding a sixth page means editing one file, not five. The machine page keeps its own stylesheet because it draws a switch, a hand and a dark room, which nothing else needs.

Everything is plain HTML, CSS and JavaScript. There is no framework, no build step, and no dependency to keep up to date.
